# Disboard Lite - Current Functionality & User Flow Documentation

This document outlines the existing frontend implementation, user journeys, and component interactions in the current React application.

## 1. Application Architecture

The application is a Single Page Application (SPA) built with:
-   **Frontend Framework**: React 19 + Vite
-   **Routing**: React Router v7
-   **Styling**: Tailwind CSS v4 + PostCSS
-   **Data State**: Client-side mock data (simulating backend responses)

## 2. current User Flows

### A. Visitor Journey (Unauthenticated)
1.  **Landing Page (`/`)**:
    -   Users arrive at a Hero section with a search bar and call-to-action.
    -   They can view "Trending Servers" (grid layout).
    -   They can browse by "Categories" (grid layout).
    -   **Action**: Clicking a server card navigates to `/server/:id`.
    -   **Action**: Clicking "Add Your Server" or "Join" attempts redirects to `/register` or `/login`.

2.  **Browse Communities (`/browse`)**:
    -   Users can filter servers by Category, Size, Language, and Tags.
    -   **Sorting**: Options for "Most Popular", "Newest", etc. (UI only).
    -   **Pagination**: UI controls for navigating pages.
    -   **Responsive Design**: Sidebar filters collapse on mobile; grid adjusts from 1 to 3 columns.

3.  **Server Details (`/server/:id`)**:
    -   Displays rich server metadata: Banner, Icon, Member Count, Online Status, Tags.
    -   **Description**: Full HTML/Markdown-supported description area.
    -   **Sidebar**: Technical stats (Creation date, Language, Owner info).
    -   **Similar Servers**: Recommendations based on tags.
    -   **Actions**: "Join Server", "Upvote", "Share".

### B. Authentication Flow
1.  **Login (`/login`)**:
    -   Standard Email/Password form.
    -   Social Login buttons (Google, Discord).
    -   **Navigation**: Link to Registration page.
    -   **Outcome**: Redirects to `/dashboard` on success (currently immediate).

2.  **Register (`/register`)**:
    -   Account creation form with Username, Email, Password.
    -   Terms of Service agreement checkbox.
    -   **Navigation**: Link to Login page.
    -   **Outcome**: Redirects to `/dashboard` on success.

### C. Server Owner Journey (Authenticated)
1.  **Dashboard Overview (`/dashboard`)**:
    -   **Layout**: Dedicated sidebar navigation (separate from public Navbar).
    -   **Stats Overview**: Total Members, Active Users, New Joins.
    -   **Recent Activity**: Feed of user interactions (joins, upvotes).
    -   **Server List**: Table view of owned servers with status (Approved, Pending, Rejected).
    -   **Quick Actions**: Edit, Boost, Analytics shortcuts.

2.  **Add Server (`/dashboard/add`)**:
    -   **Step 1: Basic Info**: Server Name, Description, Category, Language.
    -   **Step 2: Technical Config**: IP/Domain, Port, Invite Link, Tags.
    -   **Step 3: Review**: Summary and submission.
    -   **Outcome**: Adds server to the "Pending" list (UI state) and redirects to Dashboard.

## 3. Component Hierarchy

```
App
├── Layout (Public Pages)
│   ├── Navbar
│   ├── Outlet (Home, Browse, ServerDetails, Login, Register)
│   └── Footer
└── Dashboard (Protected Route)
    ├── Sidebar (Owner Navigation)
    └── Outlet (Overview, AddServer, Settings)
```

## 4. Current Limitations (Frontend Only)
-   **Data Persistence**: All changes (adding servers, registering) are lost on refresh (in-memory state).
-   **Authentication**: No real security; anyone can access `/dashboard` by typing the URL.
-   **Search/Filter**: Filtering on `/browse` is visual only; does not actually filter the list.
-   **Dynamic Content**: Server details are hardcoded Mocks; URL ID does not fetch specific data.
